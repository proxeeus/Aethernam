# G3 – segment 03dd: room script (bytecode) interpreter

Each room has up to 17 cooperative "scripts" (NPC/actor behaviour, cutscenes, triggers)
written in a compact bytecode. The scripts are loaded per room and run once per frame
(round-robin). Each one runs until it yields.

## Loading
* `01c8` loads entry `[0xce]` (room number) of the file `R00.CC4` (the name is at DSPTR(0x18a8), and seg 0053 patches
  the digits) into the 0x898-byte buffer DSPTR(0x177e) through `0008`.
* `0008` is a generic PAK/CC4 entry loader, also used by sub_0053_08f0 for `T.CC4` (the text bank that goes into DSPTR(0x325a)).
  File layout: a table of int32 file offsets, where table[0] is also the table's size in bytes. It reads 4 bytes, then table[0]-4 bytes
  into a 0x196-byte local, seeks to table[index] and reads `size` bytes. File I/O goes through sub_0e66_* (DOS wrappers).
* Script buffer: it starts with a u16 table of byte offsets (one per script), so there are `[0xd8]` = word0/2 scripts. The bytecode follows.
* `017d` resets everything, sets up each context and enables script 0 (the room init script), then runs script 0 once.
  When a savegame is being loaded (`[0x96]`!=0), sub_07fe_015c rebuilds the context pointers instead.

## Script context (DS:0x7b2 + n*0x16, n < 17). The current one is DSPTR(0x305a), and its index is [0x30a6]
+0 fptr start · +4 fptr IP · +8 s8 actor bound to the script (set by op 0x16) · +9 u8 flags ·
+0xa u16 timer or sync partner · +0xc u16 loop counter (op 0x06) · +0xe/+0x10/+0x12/+0x14 s16 zone x1,y1,x2,y2.
Flags: 0x01 wait for walk end · 0x02 wait timer · 0x04 wait for anim end · 0x08 wait for sync with script +0xa ·
0x10 wait for choice menu · 0x20 STOPPED · 0x40 wait for speech end.

## Scheduler `1ac0(n)`
Sets ctx and clears the yield flag `[0x328e]`. It returns straight away if flag 0x20 is set. Otherwise it calls, in this order, the wait handlers for
flags 08 (`187e`), 02 (`19fb`), 01 (`19b8`), 04 (`1979`), 10 (`1a7f`) and 40 (`1a23`). Each handler either clears its
flag or sets `[0x328e]`. Then: `while(!DS16(0x328e)) DSPTR(0x1946 + (*IP)*4)();`
Each handler consumes its own opcode byte (`024e`). Opcodes that block set a flag and `[0x328e]=1`.
`1b6d` runs scripts 1..[0xd8]-1 each frame. Script 0 only runs at load time.

## Bytecode encoding
* Operand fetchers: `01fb` u8 · `0213` u8*2 (X coordinates are stored halved) · `022f` s16 LE · `024e` skip ·
  `0257` relative jump: IP += s16 at IP. The offset is relative to the offset word itself.
* Conditional ops read `[rel16]`. When the condition is true they skip it (IP+=2). When it is false they jump.
* Variables: `02f0(v)`. v<0x46 → far pointer table DSPTR(0x166e+v*4) (0..41 point to actor x/y/state fields,
  0x304a random…). 0x46..0x163 → words at DS:0x11bc. 0x164..0x263 → words at DS:0xfbc.
* Value operand `03da`: `0b var16` = variable value; `0c imm8`; any other tag byte (probably 0x0d) is followed by imm16.
  That is why table slots 0x0b/0x0c/0x0d (and 0x31) are the empty `05f2`.
* IF (op 0x0a): `0a var16 cmp8 operand rel16`, where cmp is 0 ==, 1 !=, 2 >, 3 >=, 4 <, 5 <=, 6 &, 7 | (signed, `026b`).

## Speech and menu
* `165d(idx, bank)`: text bank of `*`-separated entries. It skips to the idx-th `*`, then past the next NUL.
* `169e`/`16f8` start speech through sub_0596_0405 ([0x17bc]=1). The talking anim is saved in [0x9a]/[0x32a8]/[0x329c] and restored by `1a23`.
* Choice menu (op 0x35) fills 0x306a[n] (10 bytes: text idx, fptr text, fptr of the rel16 in the bytecode).
  Another module runs the UI and clears [0x3240] after setting [0x3274]. Then `1a7f` sets IP to that pointer and jumps.

## Actor struct (DS:0x11a + i*0x46, 10 actors, hero = 0)
+0 x · +2 y · +0xe stance · +0x10 anim-lock (2=locked) · +0x12 dir · +0x14 · +0x16 fptr sprite · +0x1a anim ·
+0x1c frame · +0x20 nframes · +0x22 · +0x23 half-width · +0x24 height · +0x25 · +0x28 · +0x2a moving/active ·
+0x2c text colour · +0x30 walk flags (1|2 moving, 8 = X-walk, 0x10 = Y-walk) · +0x3c/+0x3e · +0x40/+0x41.

## Porting hazards
* **Busy-wait** in `0643` (op 0x51): four loops on [0x2d54], [0x2d4a] and [0x2d4e], which interrupts update. Every loop body
  needs `plat_yield()`. The last loop also calls rand() (sub_1215_0017) on each pass, and that must be kept.
* Far pointers held in DGROUP: ctx+0/+4 (FP(DSADDR(0x7b2+n*0x16)+4)), DSPTR(0x305a), 0x306a entries +2/+6, 0x32a2,
  0x3252, 0x177e, 0x325a, 0x18a8. IP arithmetic must go through `FP(ctx+4) += k`. **Cross-module:** sub_07fe_015c
  (savegame) rebuilds ctx+0/+4 from their raw 16-bit offsets, and the savegame probably writes the 0x7b2 block raw,
  so the IP has to be saved as an offset. The 0x306a IP pointers also cross ticks.
* 0x166e entries 42..69 are not valid pointers (they overlap other globals). Only v<42 is safe to use with DSPTR.
* Opcodes 0x0b-0x0d, 0x31 and 0x52-0x58 do not advance IP, so running them as opcodes would hang (original behaviour).
* Signed/unsigned matters: script count compares are unsigned (jb/jae), var index compares are signed, op 0x11 uses
  signed bytes (cbw), and IF compares are signed.
* `0008` passes whence as a long -1 to sub_0e66_0006 (the helper adds 1, giving SEEK_SET). The file helpers belong to another group.
