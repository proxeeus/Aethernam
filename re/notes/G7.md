# G7 – segments 0936, 0c66, 0c9b: outdoor 3D world, monsters, laser, PAK loader

**0936 (Turbo C): outdoor monsters and combat.** The actor table at DS:0x11a holds 10 slots of 0x46 bytes each. Slot 0 is the player (0x144 = player hp), and slots 1..9 are monsters.
Actor fields: +0/+2/+4 screen x/y/size of the last draw · +6/+8 world x,y · +0xa altitude · +0xc,+0xe(=4),+0x10 set by 0053_0d68
· +0x12 facing 1..4 (the anim comes from DS:0x175e[(dir+4)]) · +0x14 u8 chasing player · +0x16 fptr sprite data (loaded lazily with
sub_0053_0483(0,path[+0x42])) · +0x1a anim id · +0x1c frame · +0x1e visible this frame · +0x20 frame count · +0x22 u8 (0xff)
· +0x23/+0x24 u8 (0x10) · +0x25 u8 unpickable mask · +0x27 u8 flags (0x40 flyer, 0x80 alt draw) · +0x2a s16 hp/state (0 free, >0 alive,
-1 dying, -2/-3 death-animation chain) · +0x2d u8 heading · +0x2e u8 speed shift · +0x32/+0x34 target waypoint · +0x36 target altitude
· +0x42 path start index · +0x44 current path index.
Path table DS:0x1bbc (s16): each path is [sprite res id, flags<<8|speed, hp, ?, x0, y0, (wx,wy)*, -1]. A waypoint of (0,0) means "chase the player".
Frame flow (called from seg 0a86_154d): 0b5f runs the laser input/beam, 04f4 runs AI + anim for every monster, and 04af pushes the monsters into the 3D object list.
The 3D renderer (0a86_09af) calls 0876/056e to draw them scaled by depth. 0c14 draws the two converging laser beams (4 frames). 0e2d draws the proximity
alarm lamp and refreshes the status bar. 0d18 checks encounters: a nearby non-chasing monster sets scene 0x63. 0dc0/0df4 save and restore monsters
plus the resource-cache table (0x928, 20 x 6 bytes) around an indoor scene.

**0c66: PAK loader.** `sub_0c66_0003(name, idx)` appends ".PAK" (0f32_000d), opens the file (0e66_0031, mode 0x3ed = read), and seeks to (idx+1)*4.
It reads the entry offset and seeks to it. It then reads a long R (the reloc table size) and R-4 more bytes into a 400-byte local table (so at most 100 longs), followed by a
12-byte header {long packed, long unpacked, u8 method, u8 implode param, u16 skip}, and then seeks SEEK_CUR by skip.
It allocates with 0f27_0004: it first asks for the largest free block (-1) and needs >= unpacked+0x10cc, then allocates all of it. Method 0 reads the data raw. Method 1 reads the packed data
at buf+unpacked+0x12c-packed and calls `sub_0f48_0314(param, src, buf, unpacked, buf+unpacked+0x12c)` (PKWARE implode). Any other method loads nothing.
The block is then shrunk to `unpacked` (0f27_0079). **Relocation:** for i < table[0]/4: q = buf + table[i] - table[0]; n = P32(q)>>2; for j < n:
FP(q+4j) = q + P32(q+4j) (n is read before slot 0 is converted). The port must register these as FP slots.
Bugs to keep in mind: if open fails, the function uses the uninitialised table and pointer. The port should just return NULL (TODO). The file is closed twice for method 1.

**0c9b (hand-written asm): 3D outdoor terrain engine.** It addresses DGROUP via CS (cs:X = DS:X-0x57e0, see globals).
The world is 0x4000 x 0x4000 and split into 32x32 cells of 0x200 units. The map DSPTR(0x34a2) has 2 bytes per cell (type, height), with a row stride of 0x40.
The terrain buffer DSPTR(0x34aa) holds 4 tiles of 0x400 bytes (the player's cell + 3 neighbours, picked by 0a86_0517 from view flags 0x1fcb). Tile layout:
+0x000 vertex list (8-byte vertices), +0x320 fptr object def, +0x324 vertex count, +0x328/+0x32a world origin x,y,
+0x32c slope-class word (2 bytes from the 8-byte table CS:0x0c9b:0x00f6 = 01 00 04 05 02 03 02 03), and +0x334 three 65-byte height lines
(top c00->c01 at 0..0x40, bottom c10->c11 at 0x41..0x81, diagonal c00->c11 at 0x82..0xc2, 8 world units per sample).
Vertex = {s16 x, s16 y(depth after rotate), s16 z, u16 attr}. Pipeline: 05b2/0744 expand the defs, 01cd fills z=-height, 04f4 rotates/translates
(Q14 sin table DS:0x2d8c, >>14), 077c clips to depth>0 (buffer B 0x34ae -> A 0x34a6), 06a4 frustum-culls, 06fe projects (x*256/(d+10)+160,
z*256/(d+10)+100), and 083f compacts to 2D points for the polygon filler sub_0d84_0002. Objects/sprites: 0861 adds them to the 0x349e list, 08e8 places and
projects them, and 09ae depth-sort inserts them (0974) into the polygon stream. Player: 0404 handles input, 0464 moves, 024e flags/tile rebuild, 03e5 camera height, and 0293 the
horizon. Sky/ground: 0a15/0a66 fill the sky gradient, 0b85/0bba fill the ground, 0b20/0ae4 draw stars (time 0x1fd2 in 4..9), and 005c/0022 handle palette gradients and fades.
Blit to screen: 0c0b/0c40 copy 1:1 rows y..171, 0c70 copies at 3/4 scale, and 0ca6 at 1/2 scale (zoom mode DS:0xe6). The 386 variants are used when DS:0xec=1
(result of 0e15).

## Port hazards
* **Self-modifying code / CS variables in 0c9b** (all become locals or statics): 04f4 patches immediates cs:0x542/0x555 (cam x/y),
  0x54b/0x570 (cos) and 0x559/0x57d (sin). It also patches the **opcode** at cs:0x53f from the table cs:0x4f1 = {7d jge, 7c jl, b2 (mov dl = never jump)},
  so mode 0/1/2 becomes a switch. 01cd imm cs:0x23c and 0323 imm cs:0x3df are "saved value" temporaries. 0b20 patches the 0ae4 y offset at cs:0xaf8.
  cs:0x0e is the 04f4 temp and cs:0x0c the 077c write-only flag (both in the zero pad 0c9b:0000-0021 that follows 0c66's code).
* **Register-exact arithmetic**: 00fe interpolates with 16-bit ax/dx where al/dl carry garbage fractions. The initial AL comes from the caller
  (= low byte of 2*cell index = (uint8_t)(hmap - DSPTR(0x34a2) - 1)), DL = c11 leaks into the first step, and later steps inherit leftover dl/al.
  Its corner comparisons are **signed bytes** (jl), and the "equal" case sets bit 2 too (flags come from `or bl,4`). 05b2 in modes 0x40 leaves the high
  byte of y*8 in attr (ah not cleared). 0323 packs (product>>8) into ax via `mov al,ah / mov ah,dl`. 0c9b_005c uses a logical shr on imul results (low byte only matters).
  06fe/077c use cwd/idiv (they can trap on overflow in DOS; the port should use int32 division and truncate).
* **Row/loop edge cases**: 0a15/0a66 with horizon 0 give al=0, so 256 bands (buffer overrun). 0b85/0bba with nrows 0 loop 65536 times. 0b20 reads the star table
  past 32 columns (up to col 36). 0c0b/0c40 ignore the pointer offsets and use SS row-table offsets (SS16(y*2), end SS16(0x158) = row 172).
* **386 instructions** (eax/rep stosd/movsd/movzx/enter) appear in 0a15, 0b85 and 0c0b. 0e15 is a FLAGS-based CPU probe, so the port returns 1.
* **Memory copies of structs holding far pointers**: 0dc0/0df4 memmove the actor table (fptr at +0x16) and the resource cache (fptr at +2) with
  sub_120e_0002. The port's memmove must also move the FP side-table slots (or those pointers are lost).
* 0c66 relies on DOS "allocate largest block" and shrink. The port can malloc(unpacked+0x10cc) and realloc. The data can exceed 64 KB (huge pointer
  arithmetic), which is fine natively.
* Uses of the ISR-owned input byte DS:0x2d4a (0404, 0b5f) are one-shot reads with no busy-waits in G7. DS:0x2d66 is incremented after each view blit
  (read and cleared by the INT 8 timer ISR sub_0d7d_0046).
* 0e2d swaps DSPTR(0x2d38) to the screen buffer and hides/shows the mouse (0596_02ec/02d6) around a direct-to-screen sprite draw.
