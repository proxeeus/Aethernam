# G6 – segments 07fe, 0c05

## 07fe: save/load, options panel, resource re-linking
* **Options panel** (`0ff1`, reached from `02a7_108d`): graphics bank "a99" #0x37 in DSPTR(0x32b0), slides in/out
  over 32 frames (a 3000-byte temp made by `sub_0a21_0005`, drawn with `sub_106a_06a1`). Items (DS16 0x1b8c): 0 LOAD,
  1 SAVE, 2 Music (DS16 0xe8 = level*8, 16 gauge ticks), 3 Sound (0xea), 4 Window = 3D view size 0..2 (0xe6).
  Left/right (0x2d4a bits 4/8) change the item, down/up (bits 2/1) change the value; Enter / 'L' (0x26) / 'S' (0x1f)
  activate, Esc leaves. `0de3` redraws the panel, `0d4c` draws one gauge tick.
* **Slot menu** `0bd5(mode)` (0 = load, 1 = save; save mode skips slot 0): 10 slots, name table = 400-byte *local*
  published through DSPTR(0x32be); headers read by `0847`; rows by `08d2`/`09dc`; name entry by `0a0b`
  (AZERTY scancode table DS 0x1afe, max 38 chars / 220 px). Esc only if hero HP DS16(0x144) > 0.
* **Save file `N.AVE`** (N = '0'+slot patched into "0.ave" at DS 0x1ae4), 8000 bytes, work buffer DSPTR(0x3294):
  | offset | size | content |
  |---|---|---|
  | 0x0000 | 0x28 | slot name (NUL-terminated, plain) – also read alone by `0847` |
  | 0x0028 | 0x3e | copy of DS 0x1fba..0x1ff7 (3D-mode state: x 0x1fc2, y 0x1fc4, heading 0x1fcd, zone 0x1fd6, …) |
  | 0x0066 | 0x380 | unused (whatever the buffer held) |
  | 0x03e6 | 0x15ce | copy of DS 0x9e..0x166b (game state: room 0xa0 at +0x3e8, flags, actors 0x11a, anims 0x7b2, cache 0x928…) |
  | 0x19b4 | 0x58a | unused |
  | 0x1f3e | 2 | u16 checksum = sum of the 0x1f3e preceding bytes *as stored* (encrypted) |
  Bytes 0x28..0x1f3d are XORed with `5,10,15,…` (key = 5*(i+1) mod 256), `032a`, symmetric.
* **Load** `03ab`: read, checksum, decrypt, copy 0x1fba block. Then by current room DS16(0xa0) vs saved room
  (-1 = 3D outdoor mode): both -1 → full 3D re-init + `035d` + `0231`; switching modes → set DS16(0xa2)/(0x1fe4) and the
  pending flag DS16(0x96), the main loop (`0053_1f74`, `0a86_154d`) later calls `035d`, `03dd_01c8`(→`015c`), `0231`;
  both indoor → does it immediately. `035d` = copy savebuf+0x3e6 → DS 0x9e and restart music DS16(0xd6).
* **Resource re-linking** (needed because the saved state contains far pointers): cache table DS 0x928
  (20 × {s8 kind, s8 pakidx, fptr data}) – `0231` reloads kind-0 entries from PAK DSPTR(0x18a0), others via
  `sub_0053_03a5(kind)`, and `01d5` substitutes old→new pointer in actor field +0x16 (DS 0x11a, 10 × 0x46, each actor once,
  flags u8[10] at 0x32b4). `015c` rebases anim table DS 0x7b2 (22-byte entries, count DSU16(0xd8)) into the new
  anim resource DSPTR(0x177e) using only the 16-bit offset difference `(+4) - (+0)`. `02df` = OOM fallback: free
  all cached PAK data then reload all (heap compaction).
* Misc UI: `000e` quit-confirm box (Y/O/J/S), `00b2` fopen error handler, `06de` bevelled box, `0f88`/`0fdc` repaint 3D view background after the window size changed.

## 0c05: copy protection and 3D-world helpers
* `00fc` copy protection: "Reference : <day> <month>" (tables DS 0x22fe "01".."25", 0x22ce "JAN".."DEC",
  ref = random(192): day = ref/12, month = ref%12); answer = s16[ref] of PAK "intro" entry 2; digits via scancodes
  2..11, value kept mod 1000; Enter validates → DS16(0x11c8). `0009` draws the box.
* `01ea`/`020c`: set bit / popcount of 104-bit flag field DS 0xf6 (popcount is shown in the status panel).
* `0254` camera glide (interpolation `sub_0c9b_00d8` = a+(b-a)*i/n), `036f` scripted flight along 7 waypoints of
  DS 0x22a4 with overlay "i2" #0xc, `0400` door detection (512-unit cells, tables DS 0x21a4/0x2244),
  `0511` spawn zone objects on zone change, `056b` random encounter spawn (lists in DS 0x1bbc).

## Port hazards
1. **Far pointers inside the saved blocks.** `035d`/`057e`/`03ab` move DGROUP bytes with `sub_120e_0002`
   (movmem(src,dst,n) – note src first!). The FP side table is not copied, and the file must carry pointer
   *identities*: `0231`/`01d5` compare cache ptr (0x928+2) with actor ptr (0x11a+0x16) for equality, `015c` needs the
   16-bit offset difference of 0x7b2 +4/+0, `0231` needs NULL/non-NULL of 0x928+2. Original DOS saves hold raw
   seg:off there. Proposal: on save write a 32-bit token (low 32 bits of the native pointer) into the raw 4 bytes
   of these known slots; on load (`035d`) turn raw tokens back into fake `uint8_t*` values in the side table
   (never dereferenced: `0231`/`015c` overwrite them first). Needs agreement with owners of 0053/03dd/0936 (who
   also memcpy 0x928<->0x9a0 and 0x160<->0x41c) – a slot-aware memcpy helper in core would be cleaner.
2. `0x32be` points to a stack array of `0bd5` – fine natively (DSPTR = local array), but must not outlive it.
3. Busy-waits on DS8(0x2d4e)/DS8(0x2d4a) everywhere (000e, 00b2, 0a0b, 0bd5, 0ff1, 00fc): need `plat_yield()`.
   `0a0b`, `0bd5`, `0ff1`, `00fc` are polling loops that spin while no key is pressed.
4. Corrupted save (bad checksum): `03ab` loops on `00b2` which always returns 1 → endless error box, only the
   quit confirmation (Esc then Y) exits. fopen of a missing file loops the same way via DSPTR(0x2d40); `0847`
   sets it NULL to probe. Keep literal; file I/O helpers (`0e66_*`) take a 32-bit DOS handle (dx=0).
5. `000e`/`00b2`/`0f88` draw directly to the screen by swapping DSPTR(0x2d38) with DSPTR(0x2d3c).
6. `0c05_0254` interpolation uses 32-bit product / 16-bit idiv (can overflow on huge distances; keep int16 cast).
7. Name entry assumes AZERTY scancodes (table 0x1afe) – platform key mapping must deliver PC scancodes.
