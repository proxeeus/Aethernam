# Aethernam — Eternam for macOS

A native macOS port of **Eternam** (Infogrames, 1992), made by decompiling the original
DOS executable into C. There is no emulator inside: the game logic, the 3D island
engine, the room-script interpreter, the graphics routines and the AdLib music driver
are all C code compiled for Apple Silicon, running on a small SDL3 platform layer.

**This repository contains no game data.** You need your own copy of the original
DOS game; the app asks for its folder on first launch.

## Features

- Runs natively on macOS 11+ (arm64), resizable Retina window and fullscreen
- Upscaled display: xBR 4× edge-smoothing filter (default) or sharp pixels, 4:3 aspect
- AdLib music and sound effects through a software YM3812 synthesizer (ymfm);
  the music driver was verified register-write for register-write against the original
- English, French, German and Italian text (whatever your copy contains)
- Original save files (`0.AVE` … `9.AVE`) are compatible

## Building

Requirements: Xcode command line tools and SDL3 (`brew install sdl3`).

```sh
make                 # builds build/Eternam.app (without game data)
make run GAME_DATA=/path/to/Eternam   # run the binary directly against a game folder
```

`make BUNDLE_DATA=1 GAME_DATA=/path/to/Eternam` copies your game files *into* the app
for a self-contained personal copy. **Never distribute an app built that way.**

The app icon (`packaging/Eternam.icns`) is original artwork generated by
`tools/make_original_icon.py` (needs Pillow); it contains no game graphics.

## Game files

On first launch the app asks for the folder containing the original game (the one with
`AVE.CC1`, `RESID.PAK`, `MUS.PAK`, `A00.PAK`…`D12.PAK`, `R00.CC4`…, `T.CC4`…). The
choice is remembered in `~/Library/Application Support/Infogrames/Eternam/datadir.txt`
(delete that file to choose again). You can also pass `--data /path/to/Eternam`.

Saves and preferences live in `~/Library/Application Support/Infogrames/Eternam/`.
Existing `.AVE` files in the game folder can be loaded; new saves are written to the Application Support folder.

## Controls

| Key | Action |
|---|---|
| Arrow keys | move / choose |
| Space | fire / action |
| Tab | action bar (take, use, look, talk, inventory, disk/options) |
| Enter | confirm, skip text |
| Esc | cancel / back |
| P | pause |
| F12 | switch upscaler (xBR 4× / sharp pixels) |
| ⌘F or F11 | toggle fullscreen |
| ⌘Q | quit |

Command-line options: `--data <folder>`, `--lang en|fr|de|it|es`, `--no-intro`.

## Differences from the original

Faithful by default; these deliberate changes are documented in the code (`port:` comments):

- The code-sheet copy protection is skipped.
- Music: the title theme's channels 6–8 play (a driver reset after loading songs muted
  them) and a stopped sound effect gives its channel back to the music.
  `ETERNAM_ORIGINAL_MUSIC_BUG=1` restores the original behaviour. Songs play once, as in
  the original (jingles end, themes fall silent at their end).
- The 3D outdoor view and the inventory screen are paced at 20 frames/s (the original ran as
  fast as the CPU allowed).
- Inventory and dialogue-choice lists move one entry per key press, with auto-repeat when
  held (the original moved every frame, which only worked at 1992 CPU speeds).
- The intro program is skipped automatically if `INTRO.PAK` is damaged (some releases
  ship a truncated `SLIDE.VA2`); `ETERNAM_FORCE_INTRO=1` forces it.

## Project layout

| Path | Contents |
|---|---|
| `src/game/` | the decompiled game, one file per original code segment (`seg_SSSS.c`); functions keep their original addresses as names (`sub_SEG_OFF`) |
| `src/game/sys_*.c` | native replacements for DOS, BIOS and the hardware interrupt handlers |
| `src/intro/` | the decompiled intro program |
| `src/core/` | memory model (original data segment image, far-pointer tokens, arena), loaders and decompressors (Tatou BPE, PKWARE implode) |
| `src/platform/` | SDL3 window, input, timing, upscalers |
| `src/sound/` | AdLib driver (decompiled) + ymfm OPL2 synthesizer |
| `re/` | reverse-engineering notes (`PORTING.md`, `STAGE2.md`, `notes/`, `protos/`, `globals/`) |
| `tools/` | disassembler, listing generator, asset/decompression tools, icon generator |
| `tests/` | offline tests (decompressors, AdLib driver WAV renderer) |

How the port works in brief: the original executable is packed inside `AVE.CC1`
(byte-pair encoding). At start-up the port unpacks it only to rebuild the game's
initialised data segment. All code is C. Far pointers the game stores in memory become
32-bit tokens in their original 4 bytes, so save files and block copies behave exactly
as on DOS (see `src/core/mem.h`).
